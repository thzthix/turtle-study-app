목적:

- 구현 이력만이 아니라 의사결정 맥락을 남긴다.
- 설계 변경 이유를 나중에도 추적할 수 있게 한다.
- PM 관점과 구현 관점을 함께 연결한다.

## 2026-05-18 - 집중 세션 UI MVP 구현

### 작업 목표

- 웹에서 바로 동작하는 첫 집중 세션 경험을 만든다.
- 거북이 동행 콘셉트가 한 화면 안에서 이해되도록 구성한다.

### 구현 내용

- React + TypeScript + Vite 기반의 웹 앱 구조를 추가했다.
- `useFocusSession` 훅으로 세션 시간, 진행률, 돌봄 시점, 완료 상태를 관리하도록 분리했다.
- 집중 시간 선택, 시작, 초기화가 가능한 `SessionPanel`을 구현했다.
- SVG 기반 거북이 일러스트와 산책 경로 애니메이션을 가진 `TurtleScene`을 구현했다.
- 물 주기/당근 주기 돌봄 인터랙션을 `CarePrompt`로 분리했다.
- 완료 보상, 여정 요약, 친구 거북이 보드를 각각 별도 컴포넌트로 나눴다.
- 따뜻한 크림/세이지/살구 계열 배경과 느린 모션 중심의 스타일을 추가했다.
- `.gitignore`와 TypeScript 빌드 설정을 정리해 불필요한 생성물이 커밋 대상에 섞이지 않게 했다.

### 설계 상 고민

- 처음부터 서버나 저장 기능을 넣으면 제품의 핵심 감정선보다 구조가 앞서갈 수 있다고 판단했다.
- 그래서 이번 브랜치는 `한 번의 집중 세션이 기분 좋게 끝나는가`에만 집중했다.
- 또한 거북이 일러스트를 이미지 파일로 넣는 대신 SVG로 작성해 이후 감정 표현을 코드에서 바로 조정할 수 있게 했다.

### 구현 중 고민

- 돌봄 상호작용이 자주 뜨면 집중을 깨고, 너무 드물면 존재감이 약해질 수 있었다.
- 그래서 체크포인트를 세션 중 2회로 제한하고, 응답 후에는 다시 조용한 걷기 상태로 복귀하게 설계했다.
- 소셜 보드는 실제 기능 없이도 분위기를 줄 수 있도록, 초기에는 정적 카드 UI로 제한했다.

### 트러블슈팅

- 의존성 설치는 기본 샌드박스 상태에서 진행이 멈춰서, 권한을 올려 설치를 다시 수행했다.
- 설치 후 `npm run build`를 바로 실행해 타입과 번들 단계가 모두 통과하는지 확인했다.
- 초기 `tsc -b` 구성은 불필요한 산출 파일을 만들 수 있어서 `tsc --noEmit` 기준으로 단순화했다.

### 고려한 대안

- 대안 1: Next.js로 바로 시작하기
- 대안 2: 정적 HTML/CSS 프로토타입으로만 먼저 만들기
- 대안 3: React + TypeScript + Vite로 가볍게 시작하기

### 최종 선택과 이유

- 대안 3을 선택했다.
- 이유는 UI 상호작용과 상태 전환이 많은 제품이라 React가 적합하고, Vite가 MVP 속도와 구조 단순성 사이 균형이 가장 좋았기 때문이다.

### 남은 TODO 또는 리스크

- 실제 브라우저에서 애니메이션의 체감이 과하지 않은지 추가 확인이 필요하다.
- 세션 일시정지, 이탈 감지, 기록 저장 같은 기능은 아직 범위 밖이다.
- 디자인 완성도를 높이려면 거북이 표정 변화와 배경 디테일을 한 단계 더 다듬을 수 있다.

- 그래서 새 기능보다 `같은 기능이 더 귀엽고 더 살아있게 느껴지는가`를 우선순위로 두었다.

### 구현 중 고민

- 감정 표현을 과하게 넣으면 유치하거나 산만해질 수 있었다.

- 그래서 상태 변화는 표정, 한 줄 텍스트, 작은 장식 정도로 제한했다.

### 트러블슈팅

- 별도 타입 오류는 없었고, 변경 직후 `npm run build`로 다시 타입/번들 검증을 통과시켰다.
- 시각적 요소를 추가하면서도 컴포넌트 책임이 커지지 않게 상태별 계산 함수를 파일 내부 헬퍼로 분리했다.

### 고려한 대안

- 대안 1: Lottie나 외부 애니메이션 자산을 붙이기
- 대안 2: 캔버스 기반으로 거북이 상태를 새로 그리기
- 대안 3: 기존 SVG와 CSS 구조 안에서 표정과 상태 장식만 강화하기

### 최종 선택과 이유

- 대안 3을 선택했다.
- 이유는 MVP 단계에서 수정 가능성과 코드 가독성이 가장 중요했고, 현재 구조를 유지하면서도 충분히 귀여움을 끌어올릴 수 있었기 때문이다.

### 남은 TODO 또는 리스크

## 2026-05-18 - 친구 응원 상호작용 추가

### 작업 목표

- 소셜 요소를 무겁게 키우지 않고, 응원 중심의 가벼운 상호작용을 친구 보드에 추가한다.

### 구현 내용

- 친구 거북이 데이터에 응원 수를 추가했다.
- `FriendBoard`에서 응원 보내기 버튼과 로컬 상태 기반 응원 카운트 반영을 구현했다.
- 전체 응원 수를 보여주는 요약 영역을 추가했다.
- 친구 카드 하단 레이아웃과 버튼 스타일을 보강했다.

### 설계 상 고민

- 이 제품의 소셜은 랭킹 압박보다 `나도 버티고, 너도 버티는 중이구나`에 가까워야 한다고 판단했다.
- 그래서 친구를 이기기 위한 장치보다, 조용한 응원 행동 하나가 더 맞는 방향이라고 봤다.

### 구현 중 고민

- 실시간성이나 네트워크 저장이 없는 상태에서 소셜 인터랙션이 너무 가짜처럼 보일 수 있었다.
- 반대로 초기 MVP에 서버 연동을 넣으면 범위가 급격히 커진다.
- 그래서 이번에는 로컬 상태 기반의 짧은 응원만 허용하고, 메시지 톤으로 제품 방향을 유지했다.

### 트러블슈팅

- 구조 문제는 없었고, 구현 직후 `npm run build`로 타입과 번들 검증을 다시 통과시켰다.
- 응원 수 계산은 데이터 원본을 직접 바꾸지 않고 화면 레벨의 파생값으로 처리해 단순성을 유지했다.

### 고려한 대안

- 대안 1: 친구 간 실시간 채팅 또는 댓글 추가
- 대안 2: 순위 중심의 경쟁 보드 추가
- 대안 3: 로컬 상태 기반의 짧은 응원 버튼만 추가

### 최종 선택과 이유

- 대안 3을 선택했다.
- 이유는 현재 제품 정체성이 따뜻한 동행에 가깝고, MVP 범위 안에서 구현 비용 대비 방향 검증 효율이 가장 높았기 때문이다.

### 남은 TODO 또는 리스크

- 실제 친구 데이터와 연결되기 전까지는 정적 보드의 느낌이 남아 있다.

## 2026-05-18 - 세션 기록 저장 추가

### 작업 목표

- 웹 MVP가 한 번 실행용 데모를 넘어서도록, 오늘의 집중 기록이 로컬에 남게 만든다.

### 구현 내용

- `sessionHistory` 저장 유틸을 추가해 localStorage 읽기/쓰기를 분리했다.
- `useSessionHistory` 훅을 추가해 오늘의 세션 수, 오늘의 누적 분, 최근 기록을 파생 계산하도록 했다.
- 세션 완료 시 기록을 한 번만 저장할 수 있도록 완료 signal 기반 연결을 추가했다.
- `HistoryPanel` 컴포넌트를 추가해 오늘의 기록 요약과 최근 완료 세션을 보여주도록 했다.
- 보조 레이아웃을 auto-fit 그리드로 바꿔 카드 수가 늘어나도 자연스럽게 배치되도록 조정했다.

- focus 모드에서 장면 높이와 거북이 크기를 다시 조정해 산책길 비중을 키웠다.
- 장면 컨테이너의 카드 느낌을 약화하고, 길을 구불구불한 SVG 경로로 바꿨다.
- 거북이 이동에 작은 세로 오프셋을 더해 길을 따라 움직이는 느낌을 보강했다.

### 설계 상 고민

- 현재 UI는 정보가 많아서 제품의 첫 아이디어였던 “시간 설정 후 거북이와 길만 남는 느낌”이 약해졌다고 판단했다.
- 그래서 기능을 더 추가하기보다, 화면 단계와 정보량을 다시 정리하는 것이 우선이었다.
- 또한 카드형 껍데기가 장면 몰입을 깨고 있어서, 레이아웃뿐 아니라 표현 방식 자체도 장면형으로 옮길 필요가 있었다.

### 설계 시 고려한 대안

- 대안 1: 기존 레이아웃을 유지하고 일부 카드만 접기
- 대안 2: 세션 중 전용 화면으로 전환해 장면 중심 구조로 재배치하기
- 대안 3: 전체를 한 화면으로 두되 카드 크기만 줄이기

### 구현 중 고민

- 세션 중 정보를 너무 많이 숨기면 사용자가 남은 시간이나 제어 버튼을 찾기 어려울 수 있었다.
- 그래서 완전히 비우기보다, 작은 `FocusHud`만 남겨 기능적 정보는 유지하고 시선은 장면으로 몰아주도록 했다.
- 완료 후에는 다시 결과와 기록이 보여야 하므로, `completed` 상태는 focus와 다르게 별도 구성으로 분리했다.
- 길을 구불구불하게 만들면서도 진행률 계산은 단순하게 유지해야 해서, 실제 경로 추적 대신 시각 곡선 + 세로 오프셋 방식으로 타협했다.

### 트러블슈팅

- 기존 컴포넌트들이 한 화면 구조를 전제로 묶여 있어, 상태별 화면 분기를 App에서 다시 정리해야 했다.
- `TurtleScene`은 focus 모드에서 일부 정보만 숨기도록 props 기반 분기를 추가해 재사용성을 유지했다.
- 변경 후 `npm run build`로 타입과 번들 검증을 다시 통과시켰다.
- 카드 느낌을 줄이는 과정에서 기존 공용 `.scene-card` 스타일과 충돌할 수 있어, 장면 쪽 스타일을 부분적으로 재정의했다.

### 트러블슈팅 중 고려한 대안

- 대안 1: 아예 새로운 세션 전용 페이지 컴포넌트를 추가하기
- 대안 2: 기존 컴포넌트에 조건 분기를 넣어 상태별 표시만 다르게 하기
- 대안 3: 라우팅을 도입해 단계별 페이지처럼 나누기

### 최종 선택과 이유

- 대안 2를 선택했다.
- 이유는 현재 MVP 단계에서 구조를 과하게 늘리지 않으면서도, 원래 의도한 흐름을 빠르게 회복할 수 있었기 때문이다.

### 남은 TODO 또는 리스크

- 실제 배포 화면에서 focus 모드가 충분히 “길과 거북이만 남는 느낌”으로 읽히는지 체감 확인이 더 필요하다.
- 필요하면 다음 반복에서 focus 모드의 카피와 지원 카드 노출 타이밍을 더 줄일 수 있다.
- 거북이 실루엣 자체는 여전히 코드 SVG 기반이라, 필요하면 이미지 생성 기반 레퍼런스를 바탕으로 한 번 더 리드로잉할 수 있다.

### 구현 내용

- `vite.config.ts`에 GitHub Actions 환경에서 저장소 이름 기준 base 경로를 계산하는 설정을 추가했다.

### 설계 시 고려한 대안

- 대안 1: Vercel 같은 외부 플랫폼으로 바로 배포하기
- 대안 2: GitHub Pages로 Actions 기반 자동 배포 구성하기
