# Design Handoff Structure

## 목적

이 문서는 승인된 시안을 실제 구현으로 넘기기 전에,
개발자가 해석 없이 따라갈 수 있는 handoff 구조를 고정한다.

이번 단계의 목표는 `새로 예쁘게 만들기`가 아니라
`승인된 시안을 개발 가능한 단위로 재정리하기`다.

---

## 기준 원칙

- 시안을 새로 해석하지 않는다.
- 시안보다 예쁜 대안을 제안하지 않는다.
- 구현 편의보다 시안 유사도를 우선한다.
- 장면과 거북이가 화면의 주인공이다.
- UI는 장면 위에 조용히 얹히는 오버레이로만 다룬다.
- 자산이 승인되기 전에는 구현 반영을 밀어붙이지 않는다.

## handoff 구조

### 1. background-scene

포함:

- 하늘
- 언덕
- 길
- 꽃
- 나무
- 자연 배경만

제외:

- 시작 표지판
- 물그릇
- 당근
- 방향 표지판
- 도착 깃발
- 거북이
- UI

### 2. scene-objects

독립 자산으로 분리할 대상:

- 시작 표지판
- 물그릇
- 당근
- 방향 표지판
- 도착 깃발

### 3. turtle-states

독립 상태 자산:

- walking
- resting
- cheerful

필수 규칙:

- 셋 모두 같은 캐릭터처럼 보여야 한다.
- 상태 변화는 얼굴, 고개, 다리, 자세 높이로만 읽혀야 한다.
- 등껍질 실루엣과 질감 체계는 공유되어야 한다.

### 4. ui-overlays

구성 대상:

- 시간 선택 팝업
- 집중 HUD
- care moments
- 완료 오버레이

### 5. tokens

정의 대상:

- 컬러 팔레트
- 폰트 방향
- radius
- shadow
- spacing
- overlay opacity
- UI size rules

---

## final 기준에서 제외할 것

아래 자산은 승인된 시안을 정확히 따르지 못했으므로 final 기준 자산으로 사용하지 않는다.

- 재해석된 거북이 SVG 초안
- 재해석된 배경 SVG 초안
- 시안 기반이 아닌 감상용 handoff 화면 구현
- 장면보다 앞에 오는 카드형 UI 해석안

이 항목들은 `구현 참고`가 아니라 `제외 대상`으로 취급한다.

---

## 이번 턴의 완료 기준

- handoff 구조가 문서로 고정되어 있다.
- 자산 분리 단위가 명확하다.
- UI 오버레이 규칙이 문서로 정리되어 있다.
- 토큰 정의가 문서 또는 파일로 존재한다.
- 구현 전에 확인할 체크리스트가 있다.
- 구현 일기에 설계 판단과 제외 기준이 남아 있다.
